# Go 首轮耗时优化记录

后续内存与匹配优化见 [GO_MEMORY_OPTIMIZATION.md](GO_MEMORY_OPTIMIZATION.md)；最新测量见 [PERFORMANCE.md](PERFORMANCE.md)。

本轮保持 JavaScript 参考实现、严格比较器、原始语料与基准协议不变。目标是减少原生 Go 实现的重复遍历、字符串重建和请求内复制，不调整 GC、线程配置或清洗策略。

## 实现

- DOM 首个元素查询使用不分配的前序遍历并提前返回；只有一个文本节点时复用已有字符串。
- 空白归一化批量复制 UTF-8 区间，没有替换时返回原字符串；保留单个空白、ECMAScript 空白集合、UTF-16 长度及无效 UTF-8 修复语义。
- 序列化直接将转义结果写入最终 Builder，避免每个文本和属性的中间转义字符串。
- 作者节点先检查属性资格；候选权重只计算一次；条件清理复用后代切片和正文字符串，一次统计所需标签。
- 单次请求独占的解析树进入 ExtractOwned，省去首次防御性复制；原 Extract 保持输入不变，回退重试仍基于独立树。
- URL 字符替换器跨请求安全复用，文档 base/source 比较只计算一次。
- 未配置结构预算且上下文不可取消时跳过空验证遍历；有预算或可取消上下文仍走完整检查。
- 公开清洗流程不再计算随后立即被覆盖的原始正文。
- 属性清洗先检查危险标记的必要字符与 data-/aria- 前缀，复用匹配结果；原策略表和正则不变。

## 验证原则

不修改比较规则或 JavaScript 基准，不筛选“相同输出子集”，不缓存语料答案。DOM 局部回归包含 20,000 组混合空白和 Unicode 输入、全部 Unicode 码点的空白分类与无效 UTF-8；引擎回归覆盖两个引擎的所有权入口与回退路径。

优化前源码副本已逐项核对，与上一轮性能 manifest 中全部 Go 源码哈希相同。局部 40 段文章基准用于定位分配热点，不作为三语言最终加速比。整体结果以 [性能报告](PERFORMANCE.md) 的锁定语料和完整参数复测为准；上一轮 Rust 已兼容时的结果和原始证据保留在 performance/2026-10-27-rust-parity/。

## 最终门禁

Go 提取 **604/604**、readerability **282/282** 严格通过；Rust 同样重新复核为 **604/604** 和 **282/282**。参考源文件哈希与已采集 JavaScript 基线一致。完整 `go test -race ./...`、`go vet ./...` 和 gofmt 检查通过；20 项实际 Chromium 清洗/执行对照通过（2 项有效负面对照、13 次请求被阻止）。

门禁完成后冻结所有运行时代码和二进制，再串行测量三种实现。测量中不运行编译、测试或局部基准；原始样本及异常值全部保留。

## 正式复测结果

- Chromium：Go **1,150.20 → 691.90 ms**，观察到的降幅 **39.8%**；Go/Rust 耗时比 **2.57 → 1.51**。
- Mozilla：Go **947.81 → 655.20 ms**，观察到的降幅 **30.9%**；Go/Rust 耗时比 **1.45 → 1.20**。

两个引擎均缩小与 Rust 的全语料耗时比；Rust 仍较快，Go 的整批 RSS 仍约 112 MiB。跨轮波动存在，不把全部下降直接归因于优化。全部 261 个作业、7,560 次计时调用及离群值均保留，详见 [共享报告](PERFORMANCE.md)。优化前后完整 Go 源码和逐文件哈希已打包，便于重建和审查。
