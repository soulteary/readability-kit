# Go 第二轮内存与耗时优化

本轮先减少请求内分配，再优化引擎重复匹配。JavaScript/Rust 实现、严格比较器、原始语料、正式基准 worker、运行参数和 GC 配置均不变。

## 内存改动

- 元数据及只读元素查询采用惰性迭代，避免先收集整棵 DOM 的指针切片。
- 克隆使用源/目标父链接作为遍历路径，避免宽树的待处理栈。
- 文本聚合精确预分配；单文本仍复用原字符串。HTML 序列化估计原始输出长度后预分配，原转义逻辑不变。
- 语义清洗在请求内建立文本区间和媒体索引，避免为每个节点反复复制后代全文。前序删除祖先后跳过后代；相邻兄弟文本保持实时读取。
- 原地过滤属性，并清空切片截断位置的字符串引用，避免遗留大属性值。
- 第四次回退可直接消费准备树；前三次仍独立复制，原非拥有入口不修改调用方输入。
- 条件清理复用已计算的正文长度，减少重复全文构建与归一化。

没有跨请求缓存文章或 DOM，没有查语料答案，没有降低清洗策略或更改比较规则。

## 耗时改动

7 组简单大小写无关字面量正则使用 ASCII 自动机快路。不支持的语法和所有非 ASCII 输入回退原正则；原 pattern 不变，Unicode simplefold（包括长 s 与 Kelvin 符号）保持原行为。自动机共享只读表，匹配不分配输入缓冲。

引擎增加 30,000 组随机输入与原正则的等价测试，并覆盖全部原 pattern 字面量、锚定、Unicode 和无效 UTF-8。Go 完整 race、vet、gofmt 检查通过；提取严格差分 **604/604**、readerability **282/282** 零差异；20 项真实 Chromium 清洗/执行对照通过。Rust 也已复核 604/282，后续两轮中二进制未改动。

## 单次分配对照

这是额外 Go 诊断，不替代正式三语言实验。使用相同三个尺寸样例、相同 URL、两个引擎，执行公开提取和原生 JSON 序列化。每项 2 次预热后固定 30 次计量，输出 3 份 testing.B 报告，取 B/op 中位数。仅用于分配流量比较，计时原样保留供审计，不用于正式耗时结论。

- `rtl-4/chromium`：94,024 → 52,440 B/op，下降 44.2%。
- `rtl-4/mozilla`：93,576 → 52,048 B/op，下降 44.4%。
- `ehow-2/chromium`：2,116,278 → 1,263,021 B/op，下降 40.3%。
- `ehow-2/mozilla`：2,111,474 → 1,261,631 B/op，下降 40.2%。
- `schema-org-context-object/chromium`：5,710,325 → 3,611,928 B/op，下降 36.7%。
- `schema-org-context-object/mozilla`：5,708,036 → 3,601,931 B/op，下降 36.9%。

B/op 是累计分配流量，不是保留堆大小或峰值 RSS。只加载相同整批 JSON 输入、不执行提取的一次诊断进程，OS 峰值 RSS 为 **95.9 MiB**。它说明输入解码本身已有显著成本，不构成统计稳定下界，也不能与完整 worker RSS 相减求单篇内存。

源文件、原始 testing.B 输出与诊断进程规格均随证据保存。before 源码已逐文件核对上一轮 manifest；after 为最终冻结代码。复现需要同一仓库的原始语料及 Go 1.27.1，源快照中提供路径调整说明。

## 两个正式阶段

第一阶段只做内存优化，三语言同参数复测确认 Go 分配和中型 CLI RSS 下降，但 Go/Rust 全语料比值为 1.517/1.361，没有优于上一轮 1.506/1.196，因此继续做匹配快路。该阶段源码及全部结果单独保留，不与最终源码混用。

第二阶段包含匹配快路及正文长度复用，重新通过全部门禁后再次冻结，按相同 130 篇、种子、预热、重复次数与 261 作业串行复测。最终指标见 [PERFORMANCE.md](PERFORMANCE.md)，第一阶段记录也在其中链接。

## 最终正式结果

- Chromium：Go **691.90 → 356.95 ms**；Go/Rust **1.51 → 0.85**。
- Mozilla：Go **655.20 → 422.01 ms**；Go/Rust **1.20 → 0.78**。

最终轮中 Go 的全语料总成本低于 Rust，但中型单页和启动基线仍有 Rust 更快的情形。整批 Go RSS 仍约 113 MiB，小样例 CLI RSS 略升；中大型 CLI RSS 与分配流量下降。完整数据、两阶段历史、原始异常值与复现方式见 [PERFORMANCE.md](PERFORMANCE.md)。
